# Research ideas and hypotheses

## Establish the question boundary

Extract the field, supplied literature, available data/equipment, time constraints and intended problem. Ask only for missing information that changes the decision; label other working assumptions.
Separate user results, published findings and AI ideas. Generating an idea is not evidence of novelty.

## Find a testable angle

1. Turn broad interests into a question with a population or object, conditions, comparison and observable outcome.
2. Look for contradictions, boundary conditions, methodological limits or unexplained observations in the supplied evidence. Unsearched gaps remain candidates.
3. Develop a few substantively different options with a mechanism and falsifiable prediction; avoid renaming the same idea to fill a quota.
4. Identify the nearest existing approach and the differences that need verification. Never turn “not seen here” into “first ever.”
5. Propose a small validation that rules out at least one alternative explanation, with required data, controls, outcomes and failure conditions.
6. Compare value, evidence, access to resources, time and what can still be learned from failure. Any scores are judgments, not measurements.
7. Recommend a first option and a fallback, explaining what new information would change the ranking.

## Deliver question cards

For each candidate include the question, existing evidence, mechanism, falsifier, key control, smallest validation and resource gaps.
Separate immediately available checks from work requiring additional resources; state the decision after the first check.
Use [the experiment skill](../phd-experiment/SKILL.en.md) when formal experimental design is needed. These ideas do not establish that an experiment ran.

## Evidence and capability boundaries

- If search is available, verify the closest primary research and record the search scope and date. Otherwise supply search terms and provisional hypotheses without claiming verified novelty.
- Do not require paid search tools or an additional model when the available material supports a useful bounded comparison.
- When a file is requested, deliver a topic-selection memo. Label AI suggestions; do not attribute them to a real advisor.
- Do not create a project or change a paper percentage by default. If requested, save plans as AI-origin tasks or suggestions using the workflow below.

## Workspace synchronization (only when requested)

Read the [local workflow](../phd-manager/references/local-workflow.en.md), locate the actual repository and project, and preserve the current PHD_DATA_DIR.
Discussion, translation, drafts and suggestions do not automatically change research state. Deliver requested files to the selected directory, or outputs/ when unspecified.
For requested saves, use the CLI to read the target and current version; preserve notes, relations and user-estimated percentages rather than editing the database directly.
Use user for user facts, import for external material and ai for AI plans/assessments, preserving provenance and actual verification scope.
Validate a batch before applying multiple changes and read back successful writes before reporting them as saved. Add no fields outside the contract.

## Imported upstream resources

When the task benefits from the original methods or bundled tools, use the [GitHub integration](../github-brainstorming-research-ideas/SKILL.en.md) and read its complete upstream instructions. Check its requirements and scope; tool output does not replace the local record workflow.
