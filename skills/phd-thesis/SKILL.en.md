# Thesis integration

## Identify the thesis form

Read the institutional template, outline, existing chapters and related studies, distinguishing monograph and publication-based requirements.
Use the actual questions and available material; ask only about missing formal requirements or information that changes the overall argument.

## Build a thesis-wide argument

1. Identify the overarching question and each chapter's subquestion, separating repeated background, independent contributions and shared methods.
2. Build a question–chapter–claim–evidence–related result map to reveal disconnected chapters.
3. Order chapters logically, explaining what the previous chapter leaves open and why the next is needed; publication order alone is insufficient.
4. Reconcile shared concepts, notation, data versions and experimental settings, standardizing terms while retaining genuine condition differences.
5. Check values, figures, citations, numbering and repeated results across chapters. Explain genuine discrepancies rather than forcing them into one incorrect value.
6. Synthesize contributions, shared limitations and applicability without turning several local findings into an untested universal conclusion.
7. Check supplied authorship, collaboration, reuse and institutional requirements for published content; do not invent permissions or claim all rights are resolved.
8. List material gaps and revision dependencies, separating writing, evidence checks, formatting and new research.

## Deliver integration artifacts

Provide the requested outline, chapter transitions, glossary, consistency report or actual revised files.
Retain originals or a reviewable diff and state which chapters were processed. Unread chapters are outside the checked scope.
Chapter completion does not establish fulfillment of all degree requirements; word count is not a scientific completion metric.

## Capabilities and saving

- Verify specific formatting against available current official guidance; otherwise work from the supplied template version and state the scope.
- Without Word/LaTeX tools, provide text and structural recommendations without claiming validated headers, contents, cross-references or compilation.
- Use [paper writing](../phd-paper/SKILL.en.md) for passages and [academic translation](../phd-academic-translation/SKILL.en.md) for language work.
- A thesis may be represented by one existing papers record, but create/update it only when requested. An integration request does not authorize duplicating all component paper records.

## Workspace synchronization (only when requested)

Read the [local workflow](../phd-manager/references/local-workflow.en.md), locate the actual repository and project, and preserve the current PHD_DATA_DIR.
Discussion, translation, drafts and suggestions do not automatically change research state. Deliver requested files to the selected directory, or outputs/ when unspecified.
For requested saves, use the CLI to read the target and current version; preserve notes, relations and user-estimated percentages rather than editing the database directly.
Use user for user facts, import for external material and ai for AI plans/assessments, preserving provenance and actual verification scope.
Validate a batch before applying multiple changes and read back successful writes before reporting them as saved. Add no fields outside the contract.
