# Research proposal

## Use the current material

Identify the research question, purpose, time horizon and template or length limit. Reuse the supplied topic, data and resources; ask only about gaps that determine feasibility.
Read the selected draft, genuine preliminary work and constraints. Keep completed work separate from proposed work.

## Build a reviewable plan

1. Explain the problem, current approaches and uncertain gaps using available evidence.
2. Decompose the goal into connected questions that each have a method and a way to interpret outcomes.
3. Build a question–hypothesis–data/material–method–evaluation–deliverable matrix to expose unsupported objectives.
4. State data or sample sources, access conditions, controls, baselines and analysis assumptions. Requested data are not already available.
5. Schedule milestones from real deadlines and dependencies, resolving blocking access, equipment, data and method issues first.
6. Give major risks a trigger and an alternative. The alternative should answer the same question or explicitly narrow its scope.
7. Check that objectives, methods, time and outputs fit together; remove commitments unsupported by resources.

## Deliver a usable draft

Follow the requested template and include an evidence matrix, milestone table and unresolved checks.
Without a template, use a concise structure covering context, questions, methods, existing foundation, schedule and risks.
Describe expected outputs as goals and existing work with its actual sources. Do not invent ethics approval, collaboration commitments or advisor confirmation.

## Tools and next steps

- Verify external literature or current institutional requirements from primary sources when needed. If inaccessible, work from the supplied version and state its date/scope.
- Without Word/LaTeX capabilities, deliver Markdown text and structure without claiming formatting validation or compilation.
- Use [research ideation](../phd-ideation/SKILL.en.md) for topic comparison and [experimental design](../phd-experiment/SKILL.en.md) for detailed experiments.
- A request to draft a plan produces an artifact. Create workspace tasks only when requested; proposed milestones remain pending.

## Workspace synchronization (only when requested)

Read the [local workflow](../phd-manager/references/local-workflow.en.md), locate the actual repository and project, and preserve the current PHD_DATA_DIR.
Discussion, translation, drafts and suggestions do not automatically change research state. Deliver requested files to the selected directory, or outputs/ when unspecified.
For requested saves, use the CLI to read the target and current version; preserve notes, relations and user-estimated percentages rather than editing the database directly.
Use user for user facts, import for external material and ai for AI plans/assessments, preserving provenance and actual verification scope.
Validate a batch before applying multiple changes and read back successful writes before reporting them as saved. Add no fields outside the contract.
