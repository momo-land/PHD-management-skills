# Submission preparation

## Establish the submission target

Read the abstract, research type, audience, candidates and actual constraints, retaining the user's budget, timing and access preferences.
Compare candidates if no target is chosen. Ask only when essential budget or article-type information is missing; do not invent acceptance probabilities.

## Prepare against current requirements

1. Check scope, article types, format, anonymity, required files, deadlines and fees on official venue pages; record links and verification dates.
2. Compare the question, method and intended audience against verified scope. Leave unverified rankings or fees unknown rather than recalling current numbers from memory.
3. Map requirements to actual files, separating mandatory, conditional and optional materials.
4. Reconcile title, abstract, authors, contact details, figures, citations and supplements. For anonymous review, inspect readable content and available metadata.
5. Draft data/code availability, conflicts, funding, contributions and ethics statements only from user facts. Missing facts remain for author confirmation.
6. Draft a cover letter explaining the problem, contribution and fit without inventing editorial relationships, reviewer recommendations or exclusive-submission declarations.
7. Produce a reviewable file list with versions, missing items and uninspected formatting or metadata.

## Deliver submission materials

Provide the requested venue comparison, checklist, cover-letter draft or organized local submission package.
State the time zone for verified deadlines; do not invent a precise countdown from a date with an unknown zone.
Prepared and submitted are different states. Submission or payment requires authorization within the current task and actual successful execution.

## When access is unavailable

- Without internet access, use the supplied official-guideline version and state possible staleness. Do not give unverified current rankings, fees or deadlines.
- If PDF/Word metadata inspection is unavailable, list it as unchecked. Passing readable-content checks does not establish full anonymity.
- Basic fit comparison and material checks do not require a new paid service.
- Update records only when requested and evidenced. Complete materials do not justify papers.status=submitted; acceptance needs an actual decision.

## Workspace synchronization (only when requested)

Read the [local workflow](../phd-manager/references/local-workflow.en.md), locate the actual repository and project, and preserve the current PHD_DATA_DIR.
Discussion, translation, drafts and suggestions do not automatically change research state. Deliver requested files to the selected directory, or outputs/ when unspecified.
For requested saves, use the CLI to read the target and current version; preserve notes, relations and user-estimated percentages rather than editing the database directly.
Use user for user facts, import for external material and ai for AI plans/assessments, preserving provenance and actual verification scope.
Validate a batch before applying multiple changes and read back successful writes before reporting them as saved. Add no fields outside the contract.
