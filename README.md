# PHD-management-skills

[English documentation](README.en.md) | 简体中文

第一次使用请看 [使用说明：从启动到添加自己的论文](使用说明.md)。

一个本地运行的中英文科研工作台。用网页查看课题、论文、实验、导师反馈与文献；在网页的「AI 助手」中连接本机 Codex，或用 Codex、Claude Code、WorkBuddy 执行项目内的 skills，更新同一份科研记录。

网站和更新命令共用本地 SQLite 数据库。网页每 5 秒读取最新状态，切换 AI 客户端不会丢失已经记录的进度。查看和管理记录不需要模型。可选的 AI 助手通过本机 Codex 处理你发送的任务；使用 Codex 的 ChatGPT 登录方式时，无须填写 API Key，模型仍需联网并受账号使用额度限制。

## 启动

需要 **Node.js 24 或更新版本**。没有第三方运行依赖，无须执行 `npm install`。

macOS 可以双击项目里的 **启动工作台.command**，然后打开终端显示的网址。

在本项目目录运行：

```sh
npm start
```

打开 [本地工作台](http://127.0.0.1:4318)。首次启动会载入明确标注的示例课题。示例论文、文献、会议与实验均为演示，不能作为真实研究材料。

请通过这个 `http://` 地址访问，不要直接双击 `public/index.html`。直接打开网页文件无法读取科研记录或连接 Codex；请先启动工作台，再打开终端显示的网址。

在网页中新建自己的课题后即可开始使用。可以在数据管理菜单中清除示例；若真实记录仍关联示例课题，系统会阻止清除，需先调整关联。清空后的数据库不会在下次启动时自动恢复示例。

清除示例后，“更新记录”仍会保留操作历史。若也要清理已删除示例的历史，可让本项目中的 AI 先导出备份，再执行 `node cli.mjs clear-demo-history`。这个命令保留真实历史、现存记录的历史和 AI 对话，不会删除论文；导入旧备份可能带回其中的历史。

如果希望从完全空白的工作区开始，首次启动前运行：

```sh
node cli.mjs init
npm start
```

服务仅监听本机 `127.0.0.1`。修改端口可设置 `PORT`，例如 macOS / Linux 下运行 `PORT=4320 npm start`。在启动终端按 Ctrl+C 停止服务。

如果页面打不开，先确认启动终端仍在运行。更新项目代码后，先停止旧服务，再重新运行启动脚本或 `npm start`，最后刷新网页；只刷新页面可能仍连着旧服务，导致新功能提示“接口不存在”。重启时继续使用原来的数据目录，无需删除数据。

## 你可以做什么

| 页面 | 用途 |
| --- | --- |
| 科研总览 | 查看课题目标、论文进度、当前任务、实验和最近变化 |
| 论文管理 | 管理多篇论文、章节状态、目标投稿与自估进度 |
| 实验台账 | 记录假设、方法、对照、指标、结果、证据和产物路径 |
| 计划任务 | 设置优先级和截止日期，标记进行中、阻塞或完成 |
| 文献资料 | 登记来源、阅读状态、相关性与阅读结论 |
| 导师指导 | 记录真实会议反馈，关联后续任务；单独保存 AI 评审建议 |
| AI 助手 | 连接本机 Codex，分课题对话，发送技能指令，也可选择已有 Codex 对话导入进度 |
| Skills 中心 | 查看技能、复制调用提示、阅读执行说明 |
| 更新记录 | 回看新增、修改、删除和导入的记录 |

界面可以新增、编辑和删除记录，筛选课题，搜索内容，导入导出数据，以及生成可复制、下载的周报。周报根据数据库汇总，不会把计划中的工作写成已完成成果。

## 直接在网页里使用 Codex

先在这台电脑安装 Codex，并完成 ChatGPT 登录。然后打开工作台的 **AI 助手**：

1. 点击连接，查看 Codex 是否可用。未安装或未登录时，按页面提示完成设置后重试。
2. 新建对话并选择要讨论的课题。每个对话有自己的上下文，之后可以切换或继续。
3. 输入你的问题、进展或材料，点击发送。也可以先选择「一键更新」「导入进度」「论文写作」「实验助手」「导师反馈」「生成周报」或「论文审阅」，补充材料后发送。「导入材料」支持选择 `.txt`、`.md`、`.csv` 文件，先放入输入框，检查后再发送。
4. 回复逐步显示。需要你确认操作或补充信息时，在对应对话里处理；进行中的任务可以停止，之后发新消息继续。

例如：在绑定某个课题的对话里写“方法章节初稿已完成，论文进度估计 60%；消融实验仍在等数据”，选择「一键更新」并发送。Codex 会按项目技能读取现有记录、核对进展、通过统一更新命令保存并回读；网页随后显示保存的进度。缺少真实材料时，助手应说明缺口，不凭空增加成果。

助手最多同时处理 3 个对话中的任务；同一对话一次只处理一条消息。重新打开网页后可以查看本网站创建的会话；服务中断不会自动重发任务，确认现状后再继续。停止任务也不会撤销已经完成的文件修改或科研记录更新。网页只提供有限的单次操作确认；需要额外文件访问或其他扩展权限的工作，请在 Codex 客户端中继续。

网页使用本机 Codex 的 App Server，不模拟点击 Codex 桌面窗口。这里新建的对话是否出现在 Codex 桌面侧栏，不属于本版保证范围。Claude Code 和 WorkBuddy 仍通过下方的技能方式使用。

对话记录另存于数据目录的 `assistant/`，不包含在「数据与备份」导出的科研 JSON 中。模型回复本身不等于保存成功；以助手的执行结果、回读和更新记录为准。未发送任务时，助手不会自行开始科研工作。

### 从已有 Codex 对话导入进度

在 **AI 助手 → 从 Codex 导入** 中，按来源项目筛选或搜索，勾选最多 5 条对话，点击 **查看所选原文**，选择工作台里的目标课题，再点击 **开始整理并导入**。没有课题时，先新建课题。系统会建立一个关联目标课题的新对话，调用 `phd-import` 匹配已有记录、去重、保存并回读；原 Codex 对话保持不变。

列表只包含本机 Codex 能提供的对话；“来源项目”按这些对话的工作目录分组，不等同于桌面侧栏中的全部项目，也不自动决定工作台课题。可以继续加载列表、搜索或切换归档范围；找不到的对话可改为粘贴材料。预览显示用户和助手的文字，省略工具输出、图片与附件，长对话会标明只取了部分内容。

查看列表和预览不会调用模型或更改科研记录。点击导入后，预览文字会交给已登录的 Codex 处理，计入现有账号额度，无须填写 API Key。预览过期时重新预览；重复点击同一份导入不会启动多个任务。后续再次导入相同材料，仍按已有事实和来源去重。完成后请检查新对话的保存结果与工作台记录。详细步骤见 [使用说明](使用说明.md#从已有-codex-对话导入进度)。

## 在 AI 对话里一键更新

在 Codex、Claude Code 或 WorkBuddy 中打开本项目。新对话先调用 `phd-manager`（Codex 可输入 `$phd-manager`），之后直接说短指令即可，无须每次回到网页操作：

| 直接输入 | AI 会做什么 |
| --- | --- |
| **一键更新** | 从当前可见对话提取已完成、进行中和阻塞事项，匹配已有记录，保存后回读确认 |
| **一键导入** | 整理你提供的文字、Markdown、CSV 或指定文件中的科研材料，去重并合并进度 |
| **更新论文进度** | 更新论文阶段、章节状态和你明确给出的百分比 |
| **更新实验进度** | 登记真实实验进展、结果与证据 |
| **整理导师反馈** | 保存真实会议意见及其后续行动，AI 建议单独标注 |
| **生成周报** | 汇总最近七天变更、当前状态、阻塞和下一步 |

例如，在同一对话中先说明“论文方法章节已经完成，整体进度我估计为 60%；消融实验还没运行，正在等数据”，随后输入 **一键更新**。AI 会读取数据库，找到明确对应的论文和实验并保存；已打开的网页在下一次同步时显示新状态和进度条。进度百分比不会从聊天字数或论文阶段推算。

指令只处理 AI 当前能读取的对话与材料，不会自行读取其他聊天。多个课题无法区分时才询问目标；没有科研进展时不制造记录。外部 AI 客户端的新对话需要重新调用技能；网页 AI 助手会为本网站的对话提供项目技能与所选课题的上下文。两种方式都由 AI 执行更新，网页显示同一数据库的最新状态。

Skills 中心展示这些短指令的用法和可选的首次调用提示，另有每个技能的具体动作。Skills 中心的复制按钮只复制文本；AI 助手的发送按钮才会提交任务给 Codex。导入普通材料由 AI 阅读并组织，工作台 JSON 备份仍通过“数据与备份”恢复。

## 进度与外观

总览显示任务完成率、论文平均登记进度、实验完成率；论文看板另显示每篇论文及章节进度，课题卡片显示其任务完成率。分母和计算方式直接标在界面上，没有记录时显示“—”。这些指标用于安排工作，不代表研究质量或博士学位的完成比例。

右上角的风格按钮会打开带缩略预览的外观面板。点击卡片即可即时切换，选定后点击“完成”或按 Esc 返回工作台；浏览器自动记住选择。切换仅改变外观，当前页面、筛选、科研数据和未保存表单内容不受影响。

## 安装与使用 skills

目前提供 **39 个中英文技能入口、75 条指令**（29 个自有流程 + 10 个 GitHub 原版），覆盖选题、开题、文献综述、精读、数据检查、统计、绘图、复现、写作、返修、汇报和答辩。查看 [技能目录与用法](技能目录.md)；其中可查看 [实际引入的 GitHub 技能](docs/THIRD_PARTY_SKILLS.md)、固定来源版本和运行条件；原版脚本/参考文件已保留，额外运行库与服务没有一并安装。

在本项目运行一次：

```sh
npm run skills:install
```

它只创建本项目的适配入口，不修改用户的全局配置：

| 客户端 | 项目级入口 |
| --- | --- |
| Codex | `.agents/skills/` |
| Claude Code | `.claude/skills/` |
| WorkBuddy | `.codebuddy/skills/` |

macOS / Linux 默认使用相对目录链接，所有入口共用 `skills/` 下的原件。Windows 默认复制；也可以用 `npm run skills:install -- --copy` 复制。安装器会保护已有不同内容，不静默覆盖。复制模式下修改原件后，需要先备份并移开旧副本再重新安装。

只安装某个客户端：`npm run skills:install -- --target codex`（也支持 `claude`、`workbuddy`）。重新打开项目或刷新客户端的技能列表后使用。首次发现行为取决于客户端版本和设置；也可以让 AI 直接阅读 `skills/phd-manager/SKILL.md`。

在任一客户端中打开**整个项目目录**，例如这样说：

> 使用 phd-manager 启动本地科研工作台，创建我的课题，并根据我提供的材料建立当前研究状态。

> 使用 phd-progress，把“方法章节初稿完成，消融实验仍等待数据”的进展记录到我的课题，保留证据与待办事项。

> 使用 phd-advisor，整理这次导师会议的意见，将明确要求拆成任务，把你自己的建议单独标注。

> 使用 phd-paper，依据已有实验结果起草方法章节，缺少证据的位置保留待补标记，并更新论文进度。

> 使用 phd-weekly，生成最近七天的科研周报，区分已完成工作、当前状态、阻塞和下一步。

Codex 可显式使用 `$phd-manager`；Claude Code 可使用 `/phd-manager`。WorkBuddy 可以自然语言指定技能。三个客户端的目录适配均已提供，实际模型遵循能力和客户端自动发现仍需在对应产品中验证。

官方目录规范：[Codex](https://learn.chatgpt.com/docs/build-skills)、[Claude Code](https://code.claude.com/docs/en/skills)、[WorkBuddy](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)。

## 数据与更新命令

默认数据放在 `data/`，已在 `.gitignore` 中排除。可设置 `PHD_DATA_DIR` 为另一个绝对目录；网页服务和 AI 命令必须使用同一个目录。`.env.example` 仅用于说明，程序不会自动读取 `.env`。

周报默认使用 `Asia/Shanghai` 时区，可通过 `PHD_TIMEZONE` 指定其他 IANA 时区。`doctor` 仅检查环境与已有数据，不创建工作区。

```sh
node cli.mjs doctor
node cli.mjs state
node cli.mjs list papers
node cli.mjs report
node cli.mjs export --file backups/research.json
node cli.mjs import --file backups/research.json
node cli.mjs batch --file progress-updates.json --dry-run
node cli.mjs batch --file progress-updates.json
```

新增内容使用 JSON 文件：

```sh
node cli.mjs add projects --file my-project.json
node cli.mjs add tasks --file my-task.json
node cli.mjs update papers PAPER_ID --file paper-update.json
```

也支持 `--file -` 从标准输入读取。更新前先读取记录，提交当前 `version`；若另一个客户端已经修改，系统拒绝旧版本覆盖，需重新读取后处理差异。删除被其他记录引用的条目也会被拒绝，需先调整关联。

`batch` 供 AI 一次保存多条进度，使用 `operations` 数组列出新增和修改操作。`--dry-run` 验证整个批次而不保存；正式执行时任一项失败整批回滚。重试前回读当前状态，避免重复创建。格式见实现契约。

导入为**原子合并**，不会删除备份中没有的现有记录；任何字段、关系或版本冲突会使整次导入失败。恢复旧备份并不是强制覆盖当前数据：可在新的空数据目录导入。常规备份优先使用 JSON 导出，不要在运行期间只复制 SQLite 主文件而遗漏未合并的日志。

网页导入的请求大小上限为 2 MB；更大的备份请使用上述命令行导入。

实验标记完成需要填写结果和证据；这只检查记录是否齐全，不能证明实验真实执行或结论正确。真实导师反馈与 AI 建议分别保存，示例数据和不确定结论保持标注。

网页不加载外部字体、统计脚本或云数据库。基础科研管理可以独立使用；启用 AI 助手后，你发送的内容及 Codex 为任务读取的材料可能交给所用模型处理，遵循 Codex 的登录、权限和模型配置。网站不保存你的模型 API Key，也不读取或展示 Codex 登录令牌。

## 项目结构与验证

```text
public/          本地网页与样式
lib/             数据校验、SQLite 存储与周报
server.mjs       本地 HTTP 服务
cli.mjs          AI 与用户共用的数据更新命令
skills/          39 个双语入口、75 条指令、上游版本清单
vendor/skills/   10 个 GitHub 原版技能及许可证
scripts/         安装适配与一致性检查
fixtures/        明确标注的演示数据
tests/           数据完整性、HTTP、CLI 与适配测试
docs/            同类调研、数据协议与验收记录
data/            私有运行数据（不提交）
```

```sh
npm run check
npm test
```

测试使用临时目录，不修改真实科研数据。设计参考见 [GitHub 调研](docs/GITHUB_RESEARCH.md)，字段和接口约定见 [实现契约](docs/IMPLEMENTATION_CONTRACT.md)。

首版验收范围见 [验收记录](docs/VALIDATION.md)。

当前是面向个人本地使用的首版。没有云同步、多人账号、后台自主科研或自动连接 Zotero；文献、文件路径和实验结果通过界面或 AI 命令录入，skills 可在你提供的材料和授权范围内辅助研究。
